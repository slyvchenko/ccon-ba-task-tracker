# Офлайн-перевірка релізу й передумови відкату (v2.50.4)

Пакет `release_integrity.py` звіряє **вміст кожного файлу** source-only ZIP з SHA-256 локальних версій файлів у `release_manifest.json`. Додаткові, відсутні, змінені, дубльовані або небезпечні імена заборонені.

```bash
python release_integrity.py --root . --zip ./dist/ccon-ba-desk.zip
```

Порівняння має сенс лише якщо джерело контрольних сум походить із **незалежно довіреного релізу**. Цей механізм **не є цифровим підписом** і не засвідчує особу автора. `signerVerified=false`; незалежний ключ, перевірка provenance та підписаний release manifest потребують окремого затвердження.

`rollback_preflight()` **нічого не змінює**. Навіть після підтвердження резервної копії повертається `allowedToReplaceInstalledApp=false`, бо відсутній доказ зворотної сумісності старої програми з новою схемою SQLite. Перед будь-яким ручним відкатом потрібні незалежно перевірений rescue backup, офлайн-копія БД, тест на старому релізі, явне погодження й фіксований журнал рішення.

Синтетичні тести перевіряють коректний ZIP, підміну файлів, додаткові записи, traversal, дублі та відсутність дій із застосунком. Не використовуються живі PNR, Jira, email чи приватні дані. REL-10 залишається **PARTIAL** до незалежного підписання та Windows/SQLite backward-compatibility UAT.
