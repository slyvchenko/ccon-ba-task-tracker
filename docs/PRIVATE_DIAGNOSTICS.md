# Приватна локальна діагностика BA Desk (v2.50.0)

**Мета:** дати можливість перевірити базові ризики локального сховища та, за явною згодою, створити технічний ZIP для підтримки. Інтерфейс BA Desk і Jira/CCON не змінені. Немає мережевих викликів, фонових задач чи автоматичної відправки.

## Режим тільки перевірки

```powershell
python local_diagnostics.py check
```

Це **read-only** перевірка метаданих самої робочої папки та наперед відомих приватних шляхів BA Desk: SQLite, WAL/SHM, inbox, snapshot, data, backups, downloads, logs. Навіть якщо окремий файл має mode 0600, груповий/публічний запис до його батьківської робочої папки позначається ризиком. Жодні файли не відкриваються для читання вмісту. Для локальних supplier ZIP перевіряються лише статуси доступу до обмеженої кількості папок і файлів; їхні назви (включно з issue key, UUID і PNR) не потрапляють у звіт. Сканування папок supplier ZIP зупиняється до обходу, якщо **будь-яка перевірена батьківська downloads-папка** є symlink або небезпечного типу; у звіті `UNSAFE_ANCESTOR`. При перевищенні ліміту `complete=false` означає **неповне сканування**, а не безпеку.

Статуси `UNSAFE_SYMLINK`, `UNSAFE_SHARED_MODE`, `UNSAFE_TYPE`, `UNVERIFIED_OWNER`, `UNVERIFIED_READ_ERROR` означають, що приватність слід перевірити й усунути ризик перед роботою з реальними даними. `OWNER_ONLY_MODE` означає **лише** перевірку POSIX mode/owner, а не підтверджене шифрування. На Windows статус `UNVERIFIED_WINDOWS_ACL` **не означає безпеку**: локалізований текст icacls і членство в групах не трактуються як доказ ACL; потрібна окрема рідна Windows ACL-перевірка. Незалежно від платформи `encryptionVerified=false`.

## Експорт із явним підтвердженням

```powershell
python local_diagnostics.py export --output "C:\Users\<USER>\Documents\ba-metadata-only.zip" --confirm "EXPORT SANITIZED BA DIAGNOSTICS"
```

Замініть `<USER>` вашим користувачем і перевірте власні ACL на папку отримувача. Шлях має бути **існуючою папкою поза проєктом**, а архіву за цією назвою ще не повинно існувати. Відсутня згода, файл, який уже існує, або спроба експорту всередину проєкту забороняються. Архів створюється ексклюзивно (0600 на POSIX). На Windows ACL нового файлу успадковується від папки, отже її безпеку потрібно перевіряти окремо.

Архів містить **тільки** `diagnostics.json` (попередньо визначені технічні статуси та версія) та `README.txt`. Це редагування **виключенням**, не нестабільні регулярні вирази над реальними логами. Немає вмісту Jira, локальної SQLite, raw logs, REST, email, PNR, supplier ZIP, шляхів, user names, hostnames, токенів та secrets. Перевірте навіть такі метадані перед добровільною передачею третій стороні. Жодного upload/send у коді немає. Помилки командного рядка також навмисно приховують отримані аргументи та шляхи, навіть при неправильному використанні лапок.

## Залишковий борг

- **OPS-02 PARTIAL:** готовий локальний CLI й synthetic privacy tests, але потрібно затвердити процедуру consent/support на реальному Windows ноутбуці.
- **REL-08 PARTIAL:** реалізовано POSIX-mode і bounded/symlink/owner audit, але **не** доведено Windows NTFS DACL, системне шифрування, захист кожного можливого вкладеного ZIP і корпоративний policy. При підозрі на небезпечні права обмежити роботу з реальними локальними доказами до виправлення конфігурації.
- **Issue #50:** реальна приватна перевірка Windows/Edge/ACL/NTFS, 26 BA gold-сценаріїв та незалежне приймання залишаються відкритими. Synthetic CI не встановлює human acceptance.
