# Щотижневий WIP, блокери, завершення і переробки (v2.50.7)

Звіт читає локальну `task_history` у **SQLite mode=ro**, використовуючи історичні стани на кінець ISO-тижня (UTC). **Жодних** task ID, нотаток, email, PNR, supplier trace, вмісту станів чи шляхів не виводиться.

```powershell
python weekly_workload.py --week 2026-W43
python weekly_workload.py
```

Без `--week` використовується **останній повністю завершений тиждень**. Звіт містить три окремі класи стану на кінець тижня: `workInProgress`, `blocked`, `completedState`; тижневі переходи `completed` і `reopened`; кількість задач зі змінами, кількість історичних подій та частку блокерів серед відкритої роботи. Це не сума кнопок «Done» і не рейтинг співробітників.

Переходи рахуються **тільки якщо попередній запис цієї задачі існує**. Задача, яка вперше імпортована вже DONE, не вважається виконаною цього тижня. Переробка фіксується переходом DONE → не-DONE, незалежно від тексту нотатки. Відсутність історії не означає відсутність роботи. Результат за поточний/майбутній тиждень явно має `weekMayBeIncomplete=true`.

Записи створюються лише застосунком під час звичайного імпорту/редагування. Інструмент нічого не змінює, не планує, не надсилає і не порівнює людей. Для незалежного продуктовoго приймання потрібні фактичні BA-кейси, перевірка переходів після багатотижневих імпортів і UX-оцінка корисності огляду. Тому PRIOR-09 лишається `PARTIAL`.
