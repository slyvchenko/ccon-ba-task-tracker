# v2.33: браузерні чернетки, відновлення після перерв і доступність

**Статус:** синтетичні перевірки й code review; реальний Windows Chrome/Edge UAT, 8-годинна сесія, screen reader та 200–400% zoom залишаються OPEN. Вигляд звичайної сторінки CCON BA Desk і sprint/WRITE/score пріоритети не змінені.

## Що змінилося

- Раніше **усі вкладки писали в один ключ** `localStorage: ccon-ba-desk.unsaved-forms.v2`. Вкладка B могла переписати локальну незбережену чернетку вкладки A навіть без збереження в SQLite. Новий `assets/draft-recovery.mjs` зберігає кожну вкладку під окремим `ccon-ba-desk.unsaved-tab.v3.<tabId>` і розміщує tab ID у `sessionStorage`. Після reload у тій самій вкладці ID й чернетка залишаються.
- При першому відкритті після оновлення **старий v2 запис копіюється** у v3, а старий видаляється лише після успішного запису. Якщо браузер відмовляє у доступі до сховища, робота продовжується в пам'яті і користувач бачить **не збережено в браузері**. Немає удаваного успіху.
- При `Duplicate Tab` браузер може клонувати `sessionStorage` із тим самим ID. Нативний `BroadcastChannel` виявляє одночасно відкриті копії та перевидає ID одній вкладці, залишаючи обидві чернетки. Якщо канал недоступний, міжвкладкове об'єднання не гарантується, але **SQLite CAS** усе одно не дає мовчки перезаписати вже збережені правки.
- У звичному меню «Дані» з'явились «Відновити чернетки з іншої вкладки» та «Очистити застарілі чернетки». Відновлення потребує підтвердження та **ніколи не перезаписує незбережений запис цієї вкладки**, не видаляє чужу копію, не змінює Jira/email і зберігає первинний `baseRevision` для перевірки 409 CAS при фактичному Save.
- Інші вкладки можуть мати **закриту** сесію. Після повторного відкриття знайди її в «Дані» й віднови вручну; жодної автоматичної підміни поточної форми. Застарілі записи старші за **30 днів** не видаляються мовчки, проте оператор може видалити їх після явного попередження. Список інших вкладок показує **тільки кількість і час**, а не приватний текст.
- Валідатор відхиляє невідомі ключі, поля і неприйнятно великі тексти, зберігає максимум 100 несинхронізованих задач у вкладці, обмежує JSON payload ~3 MiB. При quota/storage error не заявляє про відновлення. Копії все ще містять незашифровані приватні Jira/email дані у браузерному профілі; **на Windows використовуйте BitLocker, особистий профіль та блокування екрана**. Очищення browser site data видалить ці резерви.

## Доступність без нового режиму

- `#list` позначено як регіон черги, пов'язаний із кількістю результатів; при **явному** переході вибрана задача оголошується через окрему тиху `aria-live=polite` область. Результати background sync не спамлять озвученням.
- Існуючі `button`, `label`, `details`, `dialog`, status + CAS alert збережено. Save status оновлюється лише при зміні тексту. Для великого масштабування додано м'якшу сітку на **320px CSS viewport** і переноси довгих кнопок. Для `forced-colors` завжди видно рамки/фокус; для `prefers-reduced-motion` немає примусової анімації чи scroll animation.
- Це **не є доказом WCAG AA**, VoiceOver/NVDA, високого контрасту Windows чи реально безгоризонтального рендерингу в кожному браузері. Не закривати A11Y без UAT.

## Data lifecycle і обмеження

1. SQLite містить тільки **підтверджені** manual status/notes/drafts. `local_backup.py` **не резервує** незбережені браузерні зміни.
2. Друк, GitHub, email, Jira, telemetry, сторонній cloud **не отримують** тексти localStorage. Довгострокове зберігання прив'язане до конкретного origin і профілю браузера.
3. При втраті з'єднання з локальним сервером typed drafts зберігаються у своїй вкладці; після відновлення все одно діє `expectedManualRevision` + 409 conflict review, не blind overwrite.
4. Відновлення з іншої вкладки є **ручним**. Якщо джерельна вкладка ще відкрита, воно не втрачає оригінал. Якщо потрібні різні варіанти тієї самої задачі, збережи власний текст окремо і порівняй зміни, не вимикаючи CAS.
5. Після закриття останньої вкладки приватні копії можуть залишатися до ручного очищення в «Дані» або browser site data. Є **30-денне попередження** для очищення інших старих вкладок, але немає тихого TTL видалення. Якщо комп'ютер спільний, очисти приватний профіль відповідно до внутрішньої політики компанії.

## Автоматичні перевірки

`tests/draft-recovery.test.mjs` має сценарії: дві незалежні вкладки із тим самим issue, reload, Duplicate Tab/rotate, міграція v2, storage quota/blocked session, ручне adopt із конфліктом, consent-based cleanup 30d, corrupted record і невідоме поле/надмірні тексти. Existing `tests/manual-edit-policy.test.mjs` та Python HTTP SQLite CAS regressions доповнюють цей coverage. `server.py` обслуговує `draft-recovery.mjs` лише за існуючим same-origin, CSP і auth. Нових HTTP endpoint або cloud write немає.

**Критерії Windows human UAT:**
1. Відкрий дві вкладки, редагуй **одну й ту саму** задачу з різними текстами, повільно та швидко. Перезавантаж кожну: обидва варіанти мають залишитися, Save в другій має показати 409.
2. Зроби Duplicate Tab, знову внеси різні правки, перевір відокремлення і ручне відновлення в меню «Дані». Закрий/відкрий браузер, перевір session restore та список orphan drafts.
3. Вимкни/заблокуй localStorage, виклич quota exceeded, перенеси старий v2 запис: має бути явне попередження або безпечна міграція без заяви про backup.
4. Підготуй синтетичні 30+-денні чернетки. Без підтвердження вони не видаляються; після підтвердження видаляються лише чужі застарілі records.
5. Windows Chrome/Edge 200% і 400% zoom на 320px CSS viewport, клавіатура, NVDA, high-contrast, довгі технічні слова/лист, modal close focus, доступність основних кнопок, жодного хибного DONE/send.
6. 8-годинна сесія (або відтворення з частими snapshot) з DevTools heap і focus traces: повторні load/import/restore не повинні зберігати старі DOM handlers або губити caret. Зафіксуй p50/p95 time-to-resume; CI сам цього не вимірює.

**Відоме обмеження:** коли браузерна функція `BroadcastChannel` вимкнена, дубльована sessionStorage ID потребує ручної перевірки. Також не реалізовано автоматичне end-to-end навантажувальне тестування у реальному Windows UI; це окремий QA-12/QA-15 backlog gate.
